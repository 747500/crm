### Производственный календарь — источники (исследование, 2026-10-03)

Сервис `packages/external` сделан (AMQP RPC, парсер ConsultantPlus), но **точная архитектура/источник
не определены — работу по календарю ОТЛОЖИЛИ**. Зафиксировано для возврата:

- **Проблема с КонсультантПлюс**: URL не всегда `.../proizvodstvennye/{year}/` — встречаются варианты
  с буквой (напр. `.../2005b`). Хардкод года — плохо. `packages/external/services/calendar.ts` сейчас
  строит URL с годом и парсит `<table class="cal">`; для годовых страниц с суффиксом надо определять
  реальный URL иначе (напр. искать год на странице, а не в URL).
- **Альтернативы**: `xmlcalendar.ru`, GitHub `iposho/holidays-calendar-ru`, `d10xa/holidays-calendar`.
- **Выбранные (самые надёжные, остановились на них)**:
  1. **Портал открытых данных РФ** — набор `7708660670-proizvcalendar` (публикуется в **CSV**).
  2. **КонсультантПлюс / Гарант** — страницы с производственным календарём (вёрстка статична годами,
     парсится за 10 минут через BeautifulSoup).
- **Решение**: источник данных — портал открытых данных (CSV) и/или КонсультантПлюс/Гарант;
  архитектуру подключения к календарю определить позже (текущий хардкод праздников в `Calendar.vue` —
  временный). См. `ROADMAP.md`.
